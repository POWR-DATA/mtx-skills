# Use Case to Data Requirements

Translate a business use case into structured data requirements.

## What this skill does

This skill takes a business problem or use case description and produces a structured set of data requirements, including required entities, source systems, grain, history, refresh cadence, and open questions.

It should be applied before pipeline, model, or platform design begins.

## When to use it

- A stakeholder has described a reporting, analytics, or operational need
- A team is scoping what data is required to support a new use case
- You need to translate vague business intent into specific data needs
- You are starting a data project and need to establish requirements before designing anything

## Example use cases

- Translating a sales performance dashboard request into data requirements
- Scoping the data needed to support a customer churn prediction model
- Identifying what operational data is required for a maintenance reporting initiative
- Defining requirements for a new finance reporting use case
